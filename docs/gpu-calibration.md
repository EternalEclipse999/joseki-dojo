# Калибровки на машине с видеокартой

Этот документ — для машины с мощной видеокартой, где запускаются тяжёлые расчёты KataGo. На машине разработки они не запускаются. Если вы Claude на этой машине и контекста разговоров у вас нет, здесь всё, что нужно знать.

## Что это за приложение

Joseki Dojo — тренажёр дзёсеки (угловых розыгрышей го) против человекоподобного KataGo:
- **Бот** играет человекоподобной сетью KataGo на заданном уровне.
- **Ходы игрока** оценивает сильная сеть KataGo: потеря в очках против лучшего хода.
- **Категория хода** (точно, неточность, ошибка, грубая ошибка) зависит от уровня игрока: потеря 1,5 очка для 7 кю допустима, для дана — нет.
- **Прогресс изучения позиции** взвешивается тем, как часто вариант встречается в партиях игроков этого уровня.

И пороги ошибок по уровням, и частоты ходов по уровням нельзя придумать: их нужно измерить. Владелец проекта отклоняет числа «с потолка». Поэтому есть калибровки: скрипты, которые измеряют это KataGo и записывают результат файлом в базы приложения (`packages/server/bases/`). Пока файла нет, приложение работает без него: с общими порогами из настроек или без показа прогресса.

## Общее для всех калибровок

1. **Ветка, не `main`.** `main` защищён и меняется только через реквест; скрипты на `main` не запускаются. Перед запуском: `git switch main && git pull`, затем `git switch -c <имя-ветки>` (имена ниже).
2. **Подготовка:**
   - `npm ci`;
   - `npm run setup` — выбрать **GPU-сборку KataGo**: на процессоре расчёт займёт дни;
   - установщик ставит и основную, и человекоподобную сеть, нужны обе.
3. **Идентичность git:** `git config user.name` и `git config user.email` должны давать имя и почту, с которыми допустим коммит. В этом репозитории это noreply-адрес GitHub из `.git/config`.
4. **Во время работы** держать машину включённой и не давать ей уснуть. Прогон порогов (раздел 1) сохраняет каждую готовую позицию и после обрыва продолжается той же командой; прогон графа (раздел 2) продолжения не имеет и начинается заново.
5. **Результат:**
   - скрипт сам коммитит только свой файл и печатает отчёт;
   - отчёт и `git show` нужно просмотреть до отправки;
   - если таблица выглядит неправильно — не отправлять, а отменить коммит (`git reset --hard HEAD~1` на чистом клоне) и сообщить владельцу.
6. **Отправка:** `git push -u origin HEAD`. Реквест в `main` владелец открывает сам: не создавать его и не сливать.

## 1. Пороги ошибок по уровням — готово к запуску

- **Ветка:** `thresholds-gpu-run`.
- **Команда:** `npm run thresholds:gpu`. Параметры по умолчанию: `--positions 400 --visits 2000 --seed 1`; `--restart` — начать заново, не продолжая сохранённый прогон.
- **Что делает:**
  - берёт 400 позиций из стартовых позиций дзёсеки;
  - смотрит, какие ходы в них играют игроки каждого уровня (человекоподобная сеть);
  - оценивает потерю каждого хода сильной сетью;
  - для каждого уровня берёт пороги неточности, ошибки и грубой ошибки — потери, которые ходы этого уровня превышают в 25 %, 10 % и 3 % случаев;
  - сглаживает: минимум 0,05, порядок «неточность < ошибка < грубая ошибка», пороги не растут с силой уровня.
- **Файл:** `packages/server/bases/thresholds.json`.
- **Время:** несколько часов на настольной видеокарте; лог раз в 20 позиций показывает, сколько осталось. `--positions` и `--visits` сокращают прогон ценой точности.
- **Если прогон прервался** (отключилось питание, упал KataGo, закрыли окно): запустить ту же команду с теми же параметрами — она продолжит после последней сохранённой позиции; теряется не больше одной позиции (около 1,5 минуты). Готовые позиции хранятся в `.gpu-runs/thresholds.jsonl` этой рабочей копии (git его не видит; в другом клоне или на другой машине прогон начнётся заново); в одной рабочей копии запускайте один прогон. Испорченный конец файла отрезается, и эти позиции считаются заново. После коммита таблицы файл удаляется сам.
- **Если запуск отказался из-за сохранения:** при другом прогоне (другие параметры, другая выборка позиций, другой KataGo) или другом коде расчёта (новый коммит в `scripts`, `packages/server/src`, `packages/shared/src` или в `starts.jdb`; незакоммиченные правки не учитываются) он называет отличие — повторить запуск с прежними параметрами и кодом или добавить `--restart`, чтобы начать с нуля; при испорченном описании прогона (первой строке файла) — `--restart`. Старое сохранение заменяется, только когда новый прогон начал считать.
- **Проверить в отчёте:**
  - пороги каждого из 30 уровней убывают от новичков к профи;
  - сколько позиций и ходов оценено;
  - все поправки сглаживания.
- **Подробности:** README, раздел «Calibrating the thresholds».

## 2. Вероятности ходов графа дзёсеки по уровням — готово к запуску

Запускать после слияния реквеста первой части «прогресса изучения дзёсеки» (спецификация `docs/superpowers/specs/2026-10-20-joseki-progress-design.md`, раздел 3.3): до слияния скрипта и графа в `main` нет.

- **Ветка:** `tree-gpu-run`, от свежего `main` (`git switch main && git pull`, затем `git switch -c tree-gpu-run`).
- **Команда:** `npm run tree:gpu`. Параметр `--threads N` (по умолчанию 16) задаёт число потоков анализа. Только на время этого запуска скрипт стартует KataGo с `numAnalysisThreads=N`, `numSearchThreadsPerAnalysisThread=1`, `nnMaxBatchSize=max(16, N)` и `nnRandomize=false`. Последнее фиксирует одну симметрию сети: повторный запуск даёт почти те же числа (побайтно они не совпадут, потому что пакеты на видеокарте складываются по-разному).
- **Что читает и пишет:** читает `packages/server/bases/joseki-graph.bin`, пишет `packages/server/bases/joseki-weights.bin`.
- **Что делает:** для каждого узла графа и каждого из 30 уровней один запрос к человекоподобной сети (один визит). Записывает вероятность каждого хода графа и тенуки; «остаток» (всё, чего в графе нет) приложение вычисляет само. По этим вероятностям приложение взвешивает прогресс изучения; без файла весов прогресс не показывается.
- **Проверки до начала:** скрипт отказывается работать на `main`, на отсоединённой голове (detached HEAD) и при незакоммиченных изменениях в файле графа или весов; сначала проверяет, что человекоподобная сеть отвечает.
- **Коммит:** скрипт коммитит только файл весов, вместе с отчётом, и печатает отчёт.
- **Размер:** 201 521 узел × 30 уровней ≈ 6,05 млн однократных запросов; файл весов — около 6–9 МБ. Время прогона пока не измерено, скорее всего это часы. Перед тем как оставить машину, посмотрите первую строку прогресса (она появляется после 1 000 узлов): в ней оценка времени. Если оценка больше суток, прервите запуск и попробуйте больший `--threads` (например, 32 или 64): по первой строке прогресса видно, стало ли быстрее.
- **Если KataGo упал:** запрос узла повторяется один раз (движок перезапускается и отправляет запросы заново); если упал и второй, запуск прекращается и ничего не пишет.
- **Как читать отчёт.** «Остаток» — вероятность хода, которого в графе нет. У узла, где записан один ход, он большой, у листа (узла без рёбер) ровно 1,0: это нормально, поэтому среднее по всем узлам (около 0,5) ничего не говорит. Отчёт даёт по каждому уровню отдельно:
  - число листьев;
  - средний остаток по узлам хотя бы с одним ребром;
  - средний остаток по узлам хотя бы с тремя рёбрами;
  - средний остаток по узлам с тенуки в пути и отдельно по узлам без тенуки (оба — среди узлов хотя бы с одним ребром);
  - пять узлов с самым большим остатком среди узлов хотя бы с тремя рёбрами, с путями.
- **Что проверить:**
  - значения должны **различаться между уровнями** и меняться плавно: одинаковые столбцы значат, что что-то не так (например, профиль уровня не применился);
  - узлы с самым большим остатком при трёх рёбрах и больше: что в них такого, не ошибка ли в графе или в разборе позиции.
- **Известное смещение:** тенуки в истории узла передаётся KataGo как пас. В пути 55 845 узлов (28 %) есть тенуки, 5 437 из них кончаются тенуки. Для таких позиций вероятности менее надёжны; поэтому отчёт считает среднее остатка по ним отдельно.

## Если что-то пошло не так

- **KataGo не отвечает человекоподобной сетью.** Скрипт остановится до начала работы: повторить `npm run setup` и проверить, что установлены обе сети.
- **Нехватка памяти видеокарты или сбои KataGo в середине.** Записать вывод и сообщить владельцу; файл не коммитится, пока прогон не закончен.
- **Сомнительная таблица в отчёте.** Не отправлять, сообщить владельцу с отчётом.
