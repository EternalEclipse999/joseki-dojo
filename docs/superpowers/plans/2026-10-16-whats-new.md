# What's New Highlight Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** After an update, the «Повторение» header button carries a «новое» mark until the player opens the section, and a one-time callout under it explains the section (spec `docs/superpowers/specs/2026-10-16-whats-new-design.md`).

**Architecture:** A list of novelties in waves (`NEWS` in `packages/shared`); the server keeps the per-player state in a new `app_state` table (migration 005) and decides at startup whether this is an update (the database already holds a training or a card) or a fresh install; `GET /api/news`, `POST /api/news/:id/seen|dismiss`. The web loads it once at startup, shows the `NewMark` pill on the section button and the `NewsCallout` under it, marks the novelty seen when the section opens.

**Tech Stack:** TypeScript, Fastify, better-sqlite3, Preact, Vitest, Playwright.

## Global Constraints

- The desktop app opens the page on a new free port at every start: browser storage does not persist; the state lives in the app database.
- Only after an update: a first start with this mechanism is an update when `sessions` or `cards` has a row; otherwise every listed novelty counts as seen.
- Waves are integers from 1, not app versions (the owner sets versions by hand).
- The mark: a quiet accent pill «новое», no animation, no dot; the due-count pill stays as it is.
- The callout: one per run, from the startup load only; «Открыть» (primary) opens the section, «Понятно» closes it, Esc closes it only when the focus is inside it; it never takes the focus and never blocks the screen; it is gone for good after «Понятно», «Открыть», Esc or a visit to the section; closing the app with it open shows it again next start.
- Opening the section by any path marks the novelty seen.
- A failed `seen` / `dismiss` behaves as a success until the next start, with no error bar; a late answer to an older action never overrides a newer one. A failed load shows no highlight and no error bar.
- Unknown novelty id → 404 `{ error: 'news_not_found' }`; repeated calls are harmless.
- User-facing text in all six catalogs (`packages/shared/src/i18n/{ru,en,ja,ko,zh-Hans,zh-Hant}.ts`); glossary row for «новое» in `docs/superpowers/specs/2026-10-14-languages-glossary.md` section 4.
- Code, comments, commits in English; commit trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; never mention the online joseki dictionary or the pro-game database.
- Every e2e server starts from a gitignored, wiped data folder; a run leaves tracked files unchanged.

- [ ] **Step 4: The service** — `packages/server/src/news/service.ts`:

```ts
import { NEWS, type NewsView } from '@joseki-dojo/shared'
import type { Db } from '../store/db'

export interface NewsItem {
  id: string
  wave: number
}

interface NewsState {
  /** The last wave taken into account. */
  wave: number
  /** The novelties to mark, in wave order. */
  unseen: string[]
  /** The novelties whose callout is not closed yet, in wave order. */
  callouts: string[]
}

export class NewsError extends Error {
  constructor(readonly code: 'news_not_found') {
    super(code)
  }
}

const KEY = 'news'

/**
 * Spec (whats-new) 3.2: which novelties are new for this player, kept in `app_state` under `news`. The first start with
 * no record is an update when the database already holds a training or a card (every listed novelty is new), a fresh
 * install otherwise (none is). Then every novelty of a later wave than the recorded one becomes new.
 */
export class NewsService {
  private state: NewsState

  constructor(
    private readonly db: Db,
    private readonly news: readonly NewsItem[] = NEWS,
  ) {
    this.state = this.start()
  }

  view(): NewsView {
    return { unseen: [...this.state.unseen], callout: this.state.callouts[0] ?? null } as NewsView
  }

  /** The player opened the novelty: no mark, no callout. */
  seen(id: string): NewsView {
    this.known(id)
    this.save({ ...this.state, unseen: this.state.unseen.filter((x) => x !== id), callouts: this.state.callouts.filter((x) => x !== id) })
    return this.view()
  }

  /** The callout was closed; the mark stays until the player opens the novelty. */
  dismiss(id: string): NewsView {
    this.known(id)
    this.save({ ...this.state, callouts: this.state.callouts.filter((x) => x !== id) })
    return this.view()
  }

  private known(id: string): void {
    if (!this.news.some((n) => n.id === id)) throw new NewsError('news_not_found')
  }

  private start(): NewsState {
    const latest = Math.max(0, ...this.news.map((n) => n.wave))
    const listed = new Set(this.news.map((n) => n.id))
    const stored = this.read()
    const base: NewsState = stored
      ? { wave: stored.wave, unseen: stored.unseen.filter((id) => listed.has(id)), callouts: stored.callouts.filter((id) => listed.has(id)) }
      : { wave: this.hasHistory() ? 0 : latest, unseen: [], callouts: [] }
    const fresh = [...this.news].filter((n) => n.wave > base.wave).sort((a, b) => a.wave - b.wave).map((n) => n.id)
    const add = (list: string[]): string[] => [...list, ...fresh.filter((id) => !list.includes(id))]
    const next = { wave: Math.max(base.wave, latest), unseen: add(base.unseen), callouts: add(base.callouts) }
    this.save(next)
    return next
  }

  private hasHistory(): boolean {
    const row = this.db.prepare('SELECT EXISTS (SELECT 1 FROM sessions) OR EXISTS (SELECT 1 FROM cards) AS h').get() as { h: number }
    return row.h === 1
  }

  /** The stored state; a missing or damaged record is none. */
  private read(): NewsState | null {
    const row = this.db.prepare('SELECT value_json FROM app_state WHERE key = ?').get(KEY) as { value_json: string } | undefined
    if (!row) return null
    try {
      const v = JSON.parse(row.value_json) as Partial<NewsState>
      const strings = (x: unknown): x is string[] => Array.isArray(x) && x.every((s) => typeof s === 'string')
      if (typeof v.wave !== 'number' || !strings(v.unseen) || !strings(v.callouts)) return null
      return { wave: v.wave, unseen: v.unseen, callouts: v.callouts }
    } catch {
      return null
    }
  }

  private save(state: NewsState): void {
    this.db.prepare('INSERT INTO app_state (key, value_json) VALUES (?, ?) ON CONFLICT (key) DO UPDATE SET value_json = excluded.value_json').run(KEY, JSON.stringify(state))
    this.state = state
  }
}
```

(TypeScript may complain that `this.state` is assigned in `save` before the constructor's assignment — the constructor assigns the result of `start()`, which is fine; if the compiler objects to the field initialisation order, declare `private state!: NewsState` and keep `this.state = this.start()`.)

import type { NewsView } from '@joseki-dojo/shared'
import type { FastifyInstance, FastifyReply } from 'fastify'
import { NewsError, type NewsService } from '../news/service'

/** Spec (whats-new) 3.3. */
export function registerNewsRoutes(app: FastifyInstance, news: NewsService): void {
  const act = (reply: FastifyReply, fn: () => NewsView): NewsView | FastifyReply => {
    try {
      return fn()
    } catch (err) {
      if (err instanceof NewsError) return reply.code(404).send({ error: err.code })
      throw err
    }
  }
  app.get('/api/news', async () => news.view())
  app.post<{ Params: { id: string } }>('/api/news/:id/seen', async (req, reply) => act(reply, () => news.seen(req.params.id)))
  app.post<{ Params: { id: string } }>('/api/news/:id/dismiss', async (req, reply) => act(reply, () => news.dismiss(req.params.id)))
}
```

import type { NewsId, NewsView } from '@joseki-dojo/shared'

export type NewsAction = 'seen' | 'dismiss'

/** Spec (whats-new) 3.4: what the app highlights — the marks, and the callout of the startup load only. */
export interface NewsShown {
  unseen: readonly NewsId[]
  callout: NewsId | null
}

export const NO_NEWS: NewsShown = { unseen: [], callout: null }

export const fromStartup = (v: NewsView): NewsShown => ({ unseen: v.unseen, callout: v.callout })

/**
 * After `seen` or `dismiss`: with no answer yet (or a failed one) the action applies locally; an answer sets the marks.
 * Either way the callout is gone for this run (spec 2.2: one callout per run).
 */
export function afterAction(shown: NewsShown, id: NewsId, action: NewsAction, answer: NewsView | null): NewsShown {
  if (answer) return { unseen: answer.unseen, callout: null }
  return { unseen: action === 'seen' ? shown.unseen.filter((x) => x !== id) : shown.unseen, callout: null }
}
```
