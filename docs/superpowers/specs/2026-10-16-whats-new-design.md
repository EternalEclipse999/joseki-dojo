# Новое в приложении: выноска и метка «новое»

- **Дата:** 2026-10-16.
- **Статус:** согласовано с владельцем.
- **Ветка:** `feat/whats-new`, от `feat/repetition-problems`. Выноска рассказывает и о задачах, поэтому ветка идёт после реквеста с ними.

## 1. Зачем

После обновления игрок не знает, что в приложении появилось новое. Первая новинка — раздел «Повторение»: позиции из дерева и задачи из ваших ошибок. Новинку нужно показать игроку, который обновился. Подсветка держится, пока он не зайдёт в раздел.

## 2. Что видит игрок

### 2.1 Метка «новое»

- **Где:** на кнопке «Повторение» в шапке, перед счётчиком карточек.
- **Вид:** спокойная пилюля в тоне акцента, текст «новое». Без анимации и без точки, чтобы не спутать её со счётчиком: залитая пилюля с числом остаётся как есть.
- **Сколько держится:** пока игрок не зайдёт в раздел «Повторение». Подходит любой путь: кнопка в шапке, «Открыть» в выноске.

### 2.2 Выноска

- **Где:** под кнопкой «Повторение», со стрелкой к ней. Показывается на экранах, где в шапке есть разделы. Во время партии и обновления KataGo разделов нет, и выноска ждёт.
- **Содержимое:**
  - заголовок «Новое: повторение»;
  - строка «Позиции из дерева и задачи из ваших ошибок возвращаются к повторению по расписанию.»;
  - кнопки «Понятно» и «Открыть» (основная).
- **Действия:**
  - «Открыть» ведёт в раздел;
  - «Понятно» закрывает выноску, метка остаётся;
  - Esc, когда фокус в выноске, действует как «Понятно». Без фокуса Esc выноску не трогает: у других экранов своё действие на Esc.
- **Когда исчезает навсегда:** после «Понятно», «Открыть», Esc или захода в раздел любым путём. Если закрыть приложение, пока выноска открыта, при следующем запуске она появится снова.
- **Фокус:** выноска не забирает фокус и не закрывает экран. Её кнопки доступны с клавиатуры (Tab после кнопок шапки).
- **Порядок показа:** не больше одной выноски за запуск. Если новинок с выноской несколько, они идут по порядку, следующая — при следующем запуске.

### 2.3 Кому

- **Только после обновления.** Первый запуск версии с этим механизмом считается обновлением, если в базе приложения уже есть хоть одна тренировка или карточка. Тогда все новинки из списка становятся новыми.
- **Чистая установка** (тренировок и карточек нет) помечает все новинки из списка как просмотренные. Ни метки, ни выноски нет.
- **Игрок, у которого уже есть карточки,** видит подсветку, как все обновившиеся: задачи для него новые. Новинка считается просмотренной только после захода в раздел.

## 3. Как устроено

### 3.1 Список новинок

- **Где:** `packages/shared`, константа `NEWS`. В ней записи `{ id, wave }`:
  - `id` — идентификатор новинки (сейчас один: `repetition`);
  - `wave` — номер волны новинок, целое число от 1.
- **Почему волна, а не версия:** номер версии владелец ставит руками при выпуске. Следующая новинка получает следующую волну, и её подхватят и те, кто уже видел прошлые.
- **Выноска** есть у каждой новинки. Тексты лежат в каталогах под ключами `news.<id>.title` и `news.<id>.text`.

### 3.2 Состояние на сервере

Хранилище браузера не подходит: настольное приложение открывает страницу на новом свободном порту при каждом запуске, и хранилище между запусками теряется. Поэтому состояние хранится в базе приложения.

- **Миграция 005:** таблица `app_state (key TEXT PRIMARY KEY, value_json TEXT NOT NULL)`. Это общее хранилище небольших состояний приложения; новости — ключ `news` со значением `{ wave, unseen: [], callouts: [] }`:
  - `wave` — последняя учтённая волна;
  - `unseen` — непросмотренные новинки (метка);
  - `callouts` — новинки, чью выноску ещё не закрыли, по порядку.
- **При запуске** сервис новостей читает состояние.
  - Если записи нет:
    - есть хоть одна тренировка (`sessions`) или карточка (`cards`) — это обновление, учтённая волна 0;
    - иначе — чистая установка, учтённая волна — последняя из списка.
  - Затем каждая новинка с волной больше учтённой попадает в `unseen` и в `callouts`, а учтённая волна становится последней из списка.
  - Состояние сразу сохраняется. Новинка из старого состояния, которой больше нет в списке, выбрасывается.

### 3.3 API

- `GET /api/news` → `{ unseen: NewsId[], callout: NewsId | null }`. `callout` — первая из `callouts`.
- `POST /api/news/:id/seen` — игрок зашёл к новинке: она уходит из `unseen` и из `callouts`. Ответ — тот же вид, что у `GET`.
- `POST /api/news/:id/dismiss` — выноску закрыли: новинка уходит из `callouts`, метка остаётся. Ответ — тот же вид.
- Неизвестный `id` → 404 `news_not_found`. Повторный вызов ничего не ломает: ответ тот же, ошибки нет.

### 3.4 Веб

- **Загрузка:** приложение загружает `/api/news` при старте.
  - Ошибка загрузки — без подсветки и без полосы ошибки (подсветка не главное), в консоль пишется строка.
  - Выноска берётся только из ответа при старте. Ответы `seen` и `dismiss` обновляют метки, а выноска после них скрывается до следующего запуска, даже если в ответе уже есть следующая (2.2: не больше одной за запуск).
  - Действие сразу применяется на экране, не дожидаясь ответа. При ошибке `seen` или `dismiss` всё остаётся как после успеха до следующего запуска, полосы ошибки нет. Запоздалый ответ на прежнее действие не перекрывает более новое.
- **Шапка** получает новости вместе с разделами: метка на кнопке раздела и выноска под ней.
- **Компонент `NewMark`** — общий, для любой кнопки или пункта. Сейчас используется только в шапке.
- **Отметка «зашёл»:** переход в раздел «Повторение» любым путём (`section === 'repetition'`) вызывает `seen`, если новинка `repetition` ещё не просмотрена.

## 4. Тексты

Новые ключи во всех шести каталогах. В глоссарий добавляется строка «новое» (метка).

- `news.badge`: «новое»;
- `news.repetition.title`: «Новое: повторение»;
- `news.repetition.text`: «Позиции из дерева и задачи из ваших ошибок возвращаются к повторению по расписанию.»;
- `news.open`: «Открыть»;
- `news.dismiss`: «Понятно».

## 5. Проверка

- **Сервер:**
  - чистая установка — ничего нового;
  - обновление (есть тренировка или карточка) — `repetition` новое и с выноской;
  - следующая волна после просмотра первой — новой становится только она;
  - `seen` и `dismiss`, повторные вызовы, неизвестный `id`;
  - состояние переживает перезапуск сервиса;
  - выбрасывание удалённой из списка новинки.
- **Сквозной тест:** отдельный сервер (порт 5185) с базой, в которую до запуска положена одна завершённая тренировка.
  - Видны выноска и метка. «Понятно» закрывает выноску, метка остаётся.
  - После перезагрузки выноски нет, метка есть.
  - Заход в «Повторение» снимает метку; после перезагрузки её нет.
- **Остальные сквозные серверы** стартуют с чистыми данными, поэтому подсветки там нет, и прежние тесты не меняются.
