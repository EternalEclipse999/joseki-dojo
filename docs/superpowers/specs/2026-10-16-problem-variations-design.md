# Варианты на экране задачи

- **Дата:** 2026-10-16.
- **Статус:** согласовано с владельцем.
- **Ветка:** `feat/problem-variations` от `main`.
- **Опирается на:** [варианты в разборе](2026-10-14-review-variations-design.md) (разделы 3–6, 8) и [задачи повторения](2026-10-15-repetition-design.md) (раздел 5.4).

## 1. Зачем

Владелец решил задачу, и лучшим оказалось тэнуки. Теперь он хочет за белых опровергнуть это тэнуки: сходить в ослабленное место и посмотреть, как KataGo будет защищаться. В разборе тренировки это уже можно: там есть варианты за обе стороны, автоответ KataGo, кандидаты с «Веткой» и «Глубже». На экране задачи после ответа доска только показывает ветку лучшего хода.

## 2. Что видит игрок

### 2.1 До ответа

Всё как сейчас. Щелчок по доске — это ответ: KataGo его оценивает, ответ записывается как повторение карточки. Исследовать позицию до ответа нельзя.

### 2.2 После ответа

Экран задачи работает как разбор партии из одного хода — вашего ответа. Вид «Ваш ответ» показывается сразу после оценки.

| | Начало задачи | Ваш ответ |
|---|---|---|
| **Доска** | позиция задачи без ответа | позиция с ответом, отметки как сейчас: круг на ответе, треугольник на лучшем ходе KataGo, крест на ходе из тренировки |
| **Кандидаты** | кандидаты позиции задачи с буквами на доске, как в разборе | те же кандидаты, как в разборе: кандидаты позиции перед ходом |
| **Щелчок по доске** | вариант вместо ответа: другой первый ход, примерка | вариант после ответа: ход соперника (например, белые в J3) |

- **Варианты** устроены как в разборе:
  - ходы за обе стороны по очереди;
  - «Отвечает KataGo» (по умолчанию включено) и «Ответить сейчас»;
  - шаги по варианту, полоса варианта с закрытием;
  - позиция варианта считается с углублением, пока она на экране;
  - у последнего хода варианта видна потеря;
  - «Ветка» и «Сыграть» в строке кандидата.
- **«Глубже»** есть для позиции задачи, как для позиций партии в разборе.
- **Навигация** — стрелки ‹ › и клавиши ← →:
  - ← с «Вашего ответа» ведёт к «Началу задачи», → обратно;
  - в варианте ← с его первого хода возвращает к виду, с которого вариант начат;
  - раньше начала задачи отмотать нельзя, дальше ответа без варианта — тоже.
- **Отдельная кнопка «Показать ветку» уходит**: её заменяет «Ветка» в строке лучшего кандидата.
- **Вердикт и панель остаются.** Варианты не меняют ни оценку повторения, ни расписание. Панель «Повторение задачи» с кнопками оценки, «Дальше» и «Закончить повторение» работают как сейчас.
- **Над вариантами — строка о видах:** «Начало задачи» / «Ваш ответ: D16» и подсказка «Щёлкните по доске, чтобы исследовать позицию».

### 2.3 Потеря первого хода после ответа

Чтобы показать потерю первого хода соперника после ответа (белые J3), нужна оценка позиции с ответом. Сервер присылает её вместе с вердиктом:
- если ответ оценивался отдельным анализом (хода нет среди кандидатов), это измеренный перевес;
- если ход есть среди кандидатов, это перевес позиции задачи минус потеря ответа, со стороны того, кто ходит.

## 3. Как устроено

### 3.1 Сервер

- **Вердикт** (`ProblemAnswer`) получает два поля:
  - `position` — сохранённый анализ позиции задачи в виде `PositionReview` (`turn: 0`, кандидаты с ветками, без ownership);
  - `leadAfter` — перевес чёрных после ответа (2.3).

  Поле `line` остаётся.
- **Карточки:** `CardService.problemBase(cardId)` возвращает `{ moves, toMove }` задачи. Для неизвестной, удалённой карточки и карточки позиции результат — `null`.
- **Варианты:** `VariationService.startProblem(owner, req, send)` по запросу `{ cardId, answer, fromTurn, moves }`:
  - `fromTurn` — 0 (вариант вместо ответа) или 1 (после ответа, тогда нужен `answer`);
  - ходы проигрываются поверх позиции задачи по очереди цветов, начиная с `toMove`;
  - кэш, углубление, поток промежуточных результатов, повтор после перезапуска KataGo и остановка — общие с вариантами разбора, без копирования.
- **Ответ сервера** — сообщение `problemVariationAnalysis { cardId, fromTurn, moves, visits, done, position }`.
- **Ошибки:**
  - неизвестная или удалённая карточка — `card_not_found` с текстом «Задачи больше нет»;
  - невозможный ход — тот же `illegal_move`, что в разборе.
- **Протокол:** новые сообщения клиента `analyzeProblemVariation { cardId, answer, fromTurn, moves }` и `stopProblemVariation { cardId }`. Сообщения разбора не меняются.

### 3.2 Веб

- **Общий хук.** Механика вариантов, которая сейчас живёт в экране разбора, выносится в общий хук. Его используют разбор и экран задачи. В хуке:
  - состояние варианта;
  - результаты анализа;
  - автоответ и «Ответить сейчас»;
  - «Глубже»;
  - выбор кандидата и ветка;
  - доска (позиция, буквы, отметки);
  - шаги и щелчок по доске;
  - потеря последнего хода.
- **Что хук получает от экрана:**
  - ходы до первой позиции;
  - ходы «партии»: у разбора — партия, у задачи — ответ;
  - сохранённые анализы позиций, где позиция может быть только с перевесом (2.3);
  - связь с сервером: запросить, остановить, последний результат, подключение, счётчик ошибок, визиты;
  - признак вида «до первого хода»: у задачи он есть, у разбора нет.
- **Поведение разбора не меняется.** Это проверяют нынешние тесты вариантов (`variation.test.ts`, `e2e/variations.spec.ts`).
- **Приложение** передаёт экрану задачи связь с сервером: последний `problemVariationAnalysis` своей карточки и запросы с `cardId` и ответом. При уходе с задачи вариант останавливается.

## 4. Тексты

Новые ключи во всех шести каталогах:
- `problem.view.start`: «Начало задачи»;
- `problem.view.answer`: «Ваш ответ: {move}»;
- `problem.explore`: «Щёлкните по доске, чтобы исследовать позицию»;
- `error.card.notFound`: «Задачи больше нет».

Ключи `problem.showLine`, `problem.hideLine` и `problem.lineStep` уже убраны в итерации 2. Кнопки ветки берутся из разбора.

## 5. Проверка

- **Сервер:**
  - вариант от задачи вместо ответа и после него;
  - цвета ходов от `toMove`;
  - невозможный ход;
  - неизвестная и удалённая карточка;
  - форма сообщения;
  - `problemBase`;
  - вердикт с `position` и `leadAfter` для хода из списка и хода вне списка.
- **Веб:** тесты чистой логики:
  - вид «до первого хода» и его границы;
  - выход из варианта к виду, с которого он начат;
  - что значит щелчок на каждом виде;
  - потеря первого хода после ответа.
- **Сквозной тест** (сервер задач, 5184): после ответа на задачу:
  - ход за соперника;
  - ответ подставного KataGo;
  - ← к ответу и к началу задачи;
  - на начале задачи нет камня ответа, щелчок даёт другой первый ход;
  - «Закончить повторение».
- **Регрессии:** нынешние сквозные тесты вариантов разбора проходят без изменений.
