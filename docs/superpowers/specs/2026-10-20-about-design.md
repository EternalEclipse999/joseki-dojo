# О программе: версия, движок, ссылки и благодарности

- **Дата:** 2026-10-20.
- **Статус:** согласовано с владельцем.
- **Ветка:** `feat/about`, от `main`. Работа идёт во временном worktree рядом с репозиторием (`D:\private\joseki-dojo-about`): основной checkout занят другой работой.

## 1. Зачем

В приложении негде посмотреть его версию. Номер нужен, чтобы сообщить об ошибке, сверить себя с релизом и понять, обновилось ли приложение. Заодно игроку нужно место, где видно, какой KataGo работает и на чём построено приложение: обычное окно «О программе».

## 2. Что видит игрок

### 2.1 Кнопка

- **Где:** в шапке, слева от глобуса языка. Круглая кнопка-иконка `Info` (lucide) того же вида, что и глобус.
- **Подпись:** «О программе» — во всплывающей подсказке (`title`) и для экранного диктора (`aria-label`).
- **Когда видна:** везде, где виден глобус, то есть на каждом экране: во время тренировки, на экране установки, на экране выбора языка.
- **Без отметки «новое».** Механизм новинок (spec whats-new) рассчитан на разделы шапки; кнопке он не нужен.

### 2.2 Окно

- **Вид:** модальное окно поверх текущего экрана (`<dialog>`, `showModal()`), фон затемнён.
- **Закрытие:** крестик в углу окна, Esc, клик по затемнению. После закрытия фокус возвращается на кнопку «О программе».
- **Фокус:** при открытии он уходит в окно, Tab не выходит за его пределы, пока окно открыто.
- **Клавиши** внутри окна не доходят до экрана под ним: стрелки не листают разбор. Esc закрывает окно.
- **Экран под окном не меняется.** Идущая тренировка, разбор, задача, установка KataGo продолжаются; окно ничего не сбрасывает и не отправляет на сервер, кроме запроса сведений (3.2).
- **Ширина:** около 28rem, на узком окне — во всю ширину с отступами; длинное содержимое прокручивается внутри окна.

## 3. Как устроено

### 3.1 Версия приложения

- **Источник один:** `version` из корневого `package.json`, как у electron-builder. `npm version` по-прежнему меняет её в одном месте.
- **Сборка:** `packages/web/vite.config.ts` читает корневой `package.json` и задаёт `define: { __APP_VERSION__: JSON.stringify(version) }`. Объявление константы — в `packages/web/src/vite-env.d.ts`.
- **Тесты:** корневой `vitest.config.ts` задаёт тот же `define`, чтобы модули с константой работали в тестах.
- Интерфейс собирается вместе с приложением (и в настольном приложении, и при запуске из исходников), поэтому зашитая версия совпадает с версией приложения. Сервер версию приложения не знает и не отдаёт.

### 3.2 API: `GET /api/about`

- **Тип** в `packages/shared` (`about.ts`, экспорт из `index.ts`):

  ```ts
  export interface AboutInfo {
    katago: {
      lockedVersion: string
      runningVersion: string | null
      setup: 'cpu' | 'gpu' | 'manual' | 'missing'
      mainModel: string
      humanModel: string
    }
  }
  ```

- **Сервис:** метод `SettingsService.about()`. У сервиса уже есть конфиг, движок, health и lock.
  - `lockedVersion` — `lock.katago.version`.
  - `runningVersion` — как на экране настроек: запрос версии у KataGo, только когда health `ready`; иначе и при ошибке запроса — `null`. Общий код с `view()` выносится в приватный метод.
  - `setup`: `missing`, если `missingFiles(config) !== null`; иначе `config.setup?.kind`, а без него — `manual`.
  - `mainModel`, `humanModel` — имя файла из `config.katago` без каталога и без расширения (`.bin.gz`, `.txt.gz`, `.bin`).
- **Маршрут:** новый файл `packages/server/src/api/about-routes.ts`, `registerAboutRoutes(app, settings)`; регистрируется в `app.ts` рядом с остальными.

### 3.3 Веб

- **`packages/web/src/about.ts`** — данные и чистые функции окна:
  - `APP_VERSION` (из `__APP_VERSION__`);
  - `PROJECT_LINKS` — три ссылки 2.3.3: ключ подписи и адрес;
  - `CREDITS` — список 2.3.4: название (не переводится) и адрес;
  - функции подписей блока «Движок» по `AboutInfo` (строка версий, строка сборки, строка сетей) — через `t`, без JSX, чтобы их можно было проверить тестом.
- **`packages/web/src/components/AboutDialog.tsx`** — окно.
  - Открыто, пока смонтировано: при монтировании `showModal()`, событие `close` (Esc, крестик) и клик по самому `<dialog>` (затемнение) вызывают `onClose`.
  - При каждом открытии запрашивает `/api/about` (`fetchAbout` в `api.ts`). Ответ не кешируется: после переустановки KataGo окно показывает новое. Ответ, пришедший после закрытия, отбрасывается.
- **`AppHeader`**: кнопка 2.1 слева от `LanguageMenu`; состояние «окно открыто» живёт в шапке. После закрытия фокус возвращается на кнопку.
- **Ссылки:** `<a href target="_blank" rel="noreferrer">`. В настольном приложении `setWindowOpenHandler` уже открывает такие ссылки во внешнем браузере; при запуске из исходников открывается новая вкладка.
- **Стили:** окно, затемнение (`::backdrop`), блоки и список благодарностей — на токенах темы, в светлой и тёмной теме.
- **Тексты:** ключи `about.*` в шести каталогах `packages/shared/src/i18n`; строка загрузки — общий `app.loading`. В глоссарий (раздел 4) добавляются строки «О программе» и «сборка (KataGo)».

## 4. Проверки

- **Сервер** (`packages/server/src/api/api.test.ts`), `GET /api/about`:
  - KataGo от установщика: `setup` — `cpu` или `gpu` по конфигу, `runningVersion` — версия фейкового KataGo;
  - пути заданы вручную (нет `setup` в конфиге): `manual`;
  - файлов KataGo нет: `missing`;
  - движок не готов: `runningVersion: null`;
  - имена сетей — без каталога и расширения.
- **Веб** (`packages/web/src/about.test.ts`): строки блока «Движок» для `cpu`, `gpu`, `manual`, `missing`, запущенного и не запущенного KataGo; `APP_VERSION` совпадает с версией из корневого `package.json`.
- **Каталоги:** существующая проверка ловит ключ `about.*`, которого нет хотя бы в одном языке.
- **e2e** (Playwright, `e2e/about.spec.ts`):
  - кнопка «О программе» открывает окно с версией из `package.json` и блоком «Движок» на фейковом KataGo;
  - Esc закрывает окно, фокус на кнопке; крестик тоже закрывает;
  - окно открывается во время тренировки; после закрытия тренировка на том же ходу.
- `npm run typecheck`, `npm test`, `npm run e2e` — зелёные.
