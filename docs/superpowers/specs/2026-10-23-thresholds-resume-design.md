# Калибровка порогов: продолжение после обрыва

- **Дата:** 2026-10-23.
- **Статус:** согласовано с владельцем (решения — раздел 7; решения 4 и 5 — после финального обзора).
- **Основа:**
  - [спецификация повторения](2026-10-15-repetition-design.md), раздел 3.3 — сама калибровка;
  - [калибровки на машине с видеокартой](../../gpu-calibration.md), раздел 1 — как её запускают.
- **Ветка:** `feat/thresholds-resume`.

## 1. Зачем

`npm run thresholds:gpu` с параметрами по умолчанию идёт около 9,5 часа (замер на RTX 4070, OpenCL: 400 позиций, 18 580 поисков по 2000 визитов). Сейчас прерванный прогон начинается заново: скачок электричества или падение KataGo на восьмом часу стоит восьми часов. После этой доработки прогон сохраняет каждую готовую позицию, и тот же запуск продолжает с места обрыва; при обрыве теряется не больше одной позиции (около 1,5 минуты).

## 2. Файл сохранения

### 2.1 Где

`.gpu-runs/thresholds.jsonl` в корне рабочей копии. Папка `.gpu-runs/` добавляется в `.gitignore`. Файл не кладётся в `packages/server/bases/`: эта папка уходит в установщик. Сохранение принадлежит рабочей копии: в другом клоне или на другой машине прогон начинается заново. В одной рабочей копии идёт один прогон.

### 2.2 Формат

JSON Lines: одна запись на строку, каждая строка заканчивается переводом строки.

- **Первая строка — описание прогона:**
  - `version` — 1;
  - `options` — `positions`, `visits`, `seed`, `coverage` этого прогона;
  - `ids` — идентификаторы выбранных стартов в порядке прогона (выборка по зерну из `starts.jdb`; идентификатор — хеш канонического пути, поэтому тот же идентификатор — те же ходы);
  - `levels` — уровни в порядке столбцов (`PLAYER_LEVELS`);
  - `code` — последний коммит, менявший код расчёта: `git log -1 --format=%H -- scripts packages/server/src packages/shared/src packages/server/bases/starts.jdb` (пустая строка, если такого коммита нет). Незакоммиченные правки кода не учитываются;
  - `katago` — версия KataGo и имена сетей (та же строка, что идёт в отчёт и в `thresholds.json`).
- **Каждая следующая строка — одна готовая позиция:**
  - `i` — её номер в `ids`, с 0;
  - `evaluated` — сколько ходов в ней оценено;
  - `seconds` — сколько секунд она считалась;
  - `samples` — для каждого уровня из `levels`, в том же порядке, список пар `[потеря, вес]`: ровно то, что позиция добавляет в распределение уровня (оценённые ходы и непокрытый остаток с потерей худшего хода).
- Числа пишутся без округления: JSON передаёт число JavaScript точно, поэтому пороги из сохранённых позиций те же, что без перерыва.

### 2.3 Запись

- Описание прогона пишется до первой позиции; каждая позиция дописывается в конец файла сразу, как готова. Файл никогда не переписывается целиком.
- После каждой строки данные принудительно сбрасываются на диск (`fsync`), чтобы при отключении питания строка не осталась в кэше.
- Позиции считаются строго по порядку, поэтому строки идут с `i` = 0, 1, 2, …
- Позиция с нечисловым или бесконечным числом не записывается: прогон сразу останавливается с ошибкой, а не находит порчу при продолжении через часы.

### 2.4 Чтение

- Читается целое начало файла: описание и идущие за ним подряд исправные позиции — строка с переводом строки, JSON нужной формы, `i` по порядку и в пределах `ids`, число столбцов равно числу уровней.
- Первая неисправная строка и всё после неё отрезаются от файла: недописанная строка, порча диска при отключении питания, строки второго прогона в той же папке. Если отрезана хотя бы одна целая строка, лог пишет `Dropped N damaged lines from the end of the save: their positions are computed again.` (недописанный хвост без перевода строки — обычный обрыв, о нём не пишется). Таблицу это не меняет: отрезанные позиции считаются заново.
- Файл без целой первой строки (питание пропало, пока писалось описание) считается пустым: прогон начинается с нуля.
- Отказ — только если первая строка целая, но не описание прогона: `The saved run in .gpu-runs/thresholds.jsonl is damaged (the first line is not a run description). Add --restart to start over.`

## 3. Запуск

### 3.1 Без сохранения

Как сейчас: проверки ветки и KataGo, затем прогон с первой позиции; описание прогона и позиции пишутся в файл (2.3).

### 3.2 С сохранением

- Тот же запуск (`npm run thresholds:gpu` с теми же параметрами) находит файл, сверяет описание с текущим прогоном и продолжает со следующей позиции после сохранённых.
- В лог одной строкой: «Continuing the saved run: 137/400 positions done» (лог скриптов — на английском, как и сейчас).
- Если сохранены все позиции (например, обрыв случился между последней позицией и коммитом), ничего не считается заново: сразу таблица, отчёт и коммит.
- Сохранение без единой позиции считается отсутствующим: прогон начинается с нуля и заменяет его. Так после падения KataGo на первой позиции можно сменить параметры без `--restart`.

### 3.3 Сохранение от другого прогона

Если описание не совпадает с текущим прогоном — другие `options`, `ids`, `levels`, `code` или `katago`, — запуск отказывается работать и называет, что отличается. `options`, `ids`, `levels` и `code` сверяются до запуска KataGo, `katago` — после проверки KataGo и до первой позиции. Например: `The saved run in .gpu-runs/thresholds.jsonl differs: visits 2000 → 500. Run with the same options to continue, or add --restart to start over.` Поля `ids` и `katago` называются без перечисления значений, если они длинные (`the sampled positions differ`); `code` — короткими хешами: `the calibration code differs (1a2b3c4 → 5d6e7f8)`. Обновление, не трогающее код расчёта (например, только документы), продолжению не мешает.

### 3.4 `--restart`

Новый флаг без значения: прогон начинается с нуля, не глядя на сохранение. Старое сохранение заменяется новым, когда новый прогон пишет своё описание — после проверки KataGo; если KataGo не запустился, старое остаётся. Остальные параметры — как раньше (`--positions`, `--visits`, `--seed`).

### 3.5 Обрыв

- **Отключение питания, закрытое окно, Ctrl+C:** в файле остаются все позиции, записанные до обрыва.
- **KataGo упал** (после одного перезапуска, как сейчас): ошибка печатается, как сейчас, и с ней строка `N/400 positions are saved in .gpu-runs/thresholds.jsonl: run the same command to continue.` Подсказка о видеокарте, которая следует за ошибкой KataGo, говорит, что меньший `--visits` при сохранённых позициях — это `--restart`: `If KataGo runs on the CPU or is too slow for --visits 2000, run npm run setup again and pick a GPU build, or lower --visits (with --restart when positions are saved).`
- Повторный запуск в обоих случаях — 3.2.

### 3.6 Успех

- После того как `thresholds.json` записан и закоммичен (или пороги не изменились и коммитить нечего), сохранение удаляется. Если удалить его не удалось, прогон всё равно успешен, а лог предупреждает: `Could not delete .gpu-runs/thresholds.jsonl: delete it by hand, or the next run with the same options continues it.`
- Если запись или коммит не удались, сохранение остаётся, и к ошибке добавляется строка `All 400 positions stay saved in .gpu-runs/thresholds.jsonl: once packages/server/bases/thresholds.json is discarded, the same command writes and commits the table again; if you commit it by hand, delete the save.` Повторный запуск (3.2) ничего не пересчитывает и снова пишет и коммитит таблицу; незакоммиченный `thresholds.json` до этого нужно убрать, иначе запуск откажется работать (4).

### 3.7 Время в логе и отчёте

- **Прогресс** (раз в 20 позиций, как сейчас): «сколько осталось» считается по скорости этого запуска — по позициям, посчитанным после старта или продолжения.
- **Отчёт и коммит:** время — сумма `seconds` всех позиций, то есть время счёта по всем запускам вместе.

## 4. Что не меняется

- Выбор позиций, ходы для оценки, потери, доли 25/10/3 %, сглаживание и формат `thresholds.json`.
- Проверки ветки: отказ на `main`, на отсоединённой голове и с незакоммиченным `thresholds.json`. Сохранение лежит в игнорируемой папке и на них не влияет.
- Скорость прогона.
- `npm run tree:gpu` остаётся без сохранений: при необходимости его можно перевести на ту же схему позже.

## 6. Проверка

Модульные тесты на поддельном движке, во временной папке:

- после каждой позиции в файле на строку больше, описание — первой строкой;
- прогон, прерванный ошибкой движка на позиции k, оставляет k позиций; повторный запуск считает только оставшиеся (движок не получает запросов по сохранённым позициям) и даёт ту же таблицу, что прогон без перерыва;
- недописанная последняя строка отбрасывается молча; порча в середине (не JSON, `i` не по порядку, другое число столбцов, позиция за пределами `ids`) отрезает её и всё после неё, сообщает число отрезанных строк, и прогон продолжает; файл после отрезания дописывается и читается снова целиком;
- испорченная (целая) первая строка — отказ; файл без целой первой строки и пустой файл — прогон с нуля;
- сохранение без позиций считается отсутствующим: другие параметры с ним не отказывают;
- другие параметры, другая выборка, другой код расчёта и другой KataGo — отказ с названием отличия; коммит, не трогающий код расчёта, продолжению не мешает; `--restart` начинает заново и заменяет сохранение;
- позиция с бесконечным числом не записывается;
- все позиции сохранены — повторный запуск не считает ничего и коммитит таблицу;
- после успешного коммита сохранение удалено; при неудачном коммите — осталось, и лог говорит, что делать;
- время в отчёте — сумма по всем запускам; оценка «осталось» — по скорости текущего запуска;
- разбор параметров: `--restart` без значения вместе с остальными.

## 7. Решения владельца

1. Продолжение после обрыва нужно до запуска калибровки порогов на 9,5 часа.
2. Повторный запуск продолжает сам, без отдельного флага; при сохранении от другого прогона — отказ и `--restart` для старта заново.
3. Сохранения — только для калибровки порогов; прогон графа не меняется.
4. Сохранение помнит коммит кода расчёта; при другом коде — отказ (`--restart` начинает заново), чтобы старые и новые позиции не смешались молча.
5. Испорченный конец файла отрезается, и прогон продолжается; отказ — только при испорченном описании прогона.
